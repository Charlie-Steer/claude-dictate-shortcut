Goal: a small Windows background program in C (Win32, single file, no
dependencies) that gives me global keyboard shortcuts for the dictation
buttons in the Claude desktop app. I want to keep Claude's own dictation,
not replace it.

What we already verified with a PowerShell UI Automation query:
- The Claude window (process name "claude") exposes its buttons through
  UI Automation as ControlType.Button with stable English names.
- Idle state: "Dictate", "Send message"
- While dictating: "Finish dictation", "Cancel dictation"
  ("Dictate" and "Send message" are absent in this state)
- AutomationIds are auto-generated (e.g. "_r_262_") and change between
  sessions. Match by Name only.
- The app builds its accessibility tree lazily: the first query returned
  only 3 window-frame buttons; a second query 3 seconds later returned
  all 68. The program needs a warm-up query and a retry loop.

Not yet verified (check these first):
- That the buttons support the Invoke pattern and that invoking "Dictate"
  really starts dictation.
- Whether Invoke works when the Claude window is not in the foreground.
- How long after "Finish dictation" the "Send message" button appears
  and becomes enabled (transcription takes a moment).

Proposed behavior:
- One global hotkey, Win+Y (via RegisterHotKey): invoke "Dictate".
- No shortcut needed for finishing or sending: Enter already finishes
  the dictation, and Enter again sends the message.
- Possible later upgrade: a low-level keyboard hook that takes over
  Win+H only while the Claude window is focused.

Implementation notes:
- RegisterHotKey for the shortcuts, IUIAutomation (COM, from C) to find
  and invoke the buttons.
- Find the window by process, not by title (the title changes per chat).
- Keep the button names as constants at the top of the file, since an
  app update may rename them.
- Check which C compiler I have installed before choosing a build setup.
- Build it in small steps and test each one against the running app.
